# MQTT: теми та поведінка

Префікс тем — `iotmodul/`. Публікація станів і підписка на команди працюють з QoS 1. Значення датчиків і станів retained, щоб новий підписник одразу отримав останній стан. Команди не зберігаються як retained.

| Теми | Напрямок | Дані |
| --- | --- | --- |
| `living/motion/state`, `bedroom/motion/state` | симулятор → openHAB | рух `ON`/`OFF` |
| `living/lux/state`, `bedroom/lux/state` | симулятор → openHAB | освітленість у люксах |
| `climate/temperature/state`, `climate/humidity/state` | симулятор → openHAB | температура та вологість |
| `power/state` | симулятор → openHAB | потужність у ватах |
| `living/light/state`, `bedroom/light/state` | симулятор → openHAB | яскравість 0–100% |
| `living/light/set`, `bedroom/light/set` | openHAB → симулятор | команда яскравості |
| `heater/state`, `heater/set` | обидва напрямки | стан та команда обігрівача |
| `heater/setpoint/state`, `heater/setpoint/set` | обидва напрямки | задана температура |
| `demo/overload/state`, `demo/overload/set` | обидва напрямки | демонстраційний сценарій перевантаження |
| `demo/away/state`, `demo/away/set` | обидва напрямки | демо «Нікого вдома»: симулятор зупиняє рух, таймер порожньої квартири — 30 с |
| `status/simulator`, `status/openhab` | клієнт → брокер | LWT `OFFLINE`, birth `ONLINE`, retained, QoS 1 |

Паролі OpenHAB та симулятора різні. ACL надає OpenHAB читання станів і запис команд, а симулятору — читання команд і запис станів. TLS CA та приватні ключі генеруються локально при першому запуску й не зберігаються в Git.

## Демонстраційні сценарії

1. Зміна руху та освітленості в кімнатах автоматично змінює димери.
2. Температура коливається навколо заданого режиму; правила керують обігрівачем.
3. Перемикач тесту перевантаження створює 2700 Вт. Якщо рівень тримається понад хвилину, OpenHAB відображає сповіщення та вимикає обігрівач.
4. Симулятор змінює дані кожні дві секунди; у панелі є графік потужності за годину.
